# CreateX 运营平台设计

状态：先保存设计及backlog，再实施。目标用户：核心团队与城市负责人同时使用。

## 用户路径

官网以 AI × Design Thinking 为主线：教育、工作和社区面对AI变革，通过真实问题、跨角色工作坊、4–8周项目与证据复盘推进。主入口为“找到本地社区”。GIS显示社区状态与城市定位，不把地理坐标当成已建立社区的证据；未核实社区不得展示为已开放。

访客：选城市/地图 → 看已核实公开社区 → 使用真实联系入口；没有社区时准备本地筹建意向，不假称报名成功。地理定位只在主动请求后使用，不保存精确个人位置。手动搜索与列表始终可用。

核心运营：全局概览 → 城市审核 → 分配城市负责人 → 招募跟进 → 工作坊 → 项目与验收 → 贡献与复盘。城市负责人只能访问其被分配城市。全局授权与城市公开状态由核心团队管理。

## 首版数据及边界

城市社区：经纬度、状态、公开名称/介绍、已核实联系URL；私有负责人权限独立管理。招募：联系字段、问题、意向角色、状态及跟进。工作坊：真实问题、时间、负责人、交付证据。项目：里程碑、期限、验收证据。贡献：事项、工时、证据、独立验收。所有记录包含版本、修改时间及审计事件。

首版不提供支付、代币、个人股权、自动认证、自动法律签署。既有私下文件不导入公开数据库。无虚构已运营城市。真实管理员邮箱另存在私有配置，不能提交公共仓库。

## 技术

monorepo新增 apps/operations。Cloudflare Worker + D1，准备生产适配与本地持久数据库。身份验证优先Cloudflare Access，服务端验证JWT签名/issuer/audience/过期；缺失配置时拒绝私有API。开发身份严格限定本机开发环境，不可用于生产。每个API执行城市范围校验，修改采用乐观并发控制及审计事务；跨站写入拒绝。

GIS采用Leaflet，保留OSM署名，底图按需加载，不预取、不批量下载；不依赖公共地理编码做每键搜索。参考城市目录只作地理检索，不代表活跃社区。生产社区来自被明确批准公开的数据。

## 上线门槛

通过权限负向测试、数据库持久化/并发测试、双语GIS空态与降级、手机及缩放布局、真实公开联系流程，保存数据库备份/回退；管理员验证接通后才启用生产私有管理。不把本地演示视为生产已可登录。
