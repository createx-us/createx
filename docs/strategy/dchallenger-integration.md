# CreateX × D-Challenger 整合方案

日期：2026-11-05。状态：运营与产品提案；不是已签合作、平台上线或城市成立公告。

## 依据及采用范围

依据用户指定分享《Develop CreateX–D-Challenger model》：https://chatgpt.com/s/cx_6aebf04a31f0819191bc22c9b15722a2 。本方案吸收其中挑战平台、城市/全球社区、企业节点和大学问题导向学习的概念，不公开转载私人邮件、联系资料、创始人名单或附件。分享中的 AI 生成建议并非已核实机构承诺。GDTA 的角色、D-Challenger 品牌/平台权属和商业关系需各方另行确认。

## 定位与差异

CreateX 保留社区、引导师、AI × Design Thinking、工作坊及持续实践能力；吸收 D-Challenger 的挑战发现、匹配、团队协作、实施跟踪，使工作坊进入可持续交付过程。对外主体仍为 CreateX。不是重命名、公司合并，也不宣称 D-Challenger 已属于 CreateX。

共同目标：用真实挑战发展人与组织的创新能力，并在真实场景验证成果。共同流程：发现定义 → 准备度检查 → 人与能力匹配 → 共创原型 → 项目实施 → 验收复用。Workshop OS 是实践单元，4–8周项目是一种路径，大学学期或其他周期按场景确定。

## 四类参与环境

1. 城市社区是基础：真实情境、重复协作和信任、跨机构资源与实施接收方集中在本地。城市可覆盖都市圈及周边，不授予行政区域独占。上述价值是试点假设，不能由活动人数直接推出成效。
2. 全球虚拟社区按议题或能力组织；无本地社区者可参与。全球项目仍需负责人、验证场景和接收方；不制造虚拟城市或虚假GIS标记。
3. 企业节点在企业内落地同一实践模式。可选择内部、指定伙伴、公开简报三种挑战范围；企业边界不因网络连接而消失。
4. 大学项目将合适挑战转为问题导向学习、跨学科课程或研究。大学负责课程、指导与评价；挑战方提供场景和反馈；城市社区负责伙伴协调及跨届交接。学习成绩和实际采用分别评价。

成熟城市社区拟议条件：非营利组织、企业、政府或公共机构、大学或其他学习机构持续参与，定义贡献与责任，受影响居民共同定义/验证问题。筹建社区应披露缺口；不是要求每个项目都有全部部门，也不是要求把政府支持当成启动前既成事实。

## 角色与决策

| 角色       | 承担                                   | 边界                                       |
| ---------- | -------------------------------------- | ------------------------------------------ |
| 挑战负责人 | 问题真实性、授权简报、利益相关方和资源 | 不是自动获得所有数据访问权                 |
| 城市协调人 | 本地伙伴、引导师、持续跟进             | 限已分配城市；无跨城签约权                 |
| 引导师     | 过程质量、协作和证据                   | 不代替机构批准实施                         |
| 大学负责人 | 教学、监督、评价、学生参与安排         | 不保证企业采用或无偿学生劳动               |
| 接收机构   | 试点/实施决定、资源与实际结果验收      | 必须明确具名责任人                         |
| 全球贡献者 | 专业支持及经约定交付                   | 只访问获准材料                             |
| AI         | 研究、翻译、匹配建议、原型和记录辅助   | 不能自动批准人选、发布材料、授权或认定成效 |

## 后台数据模型增量（未实现）

- Organization/Node：机构类型、城市、企业/大学/非营利/公共参与身份、核实状态和授权代表；公开组织资料与私人联系人分开。
- Challenge：owner、city或global_scope、问题/基线、受影响对象、可用资源、周期、可见范围 internal/partners/public、版本及准备度状态。
- ChallengeAccess：指定机构/项目成员、权限、到期与撤回；城市角色不自动获得企业内部挑战。
- MatchProposal：能力、可投入时间、语言、依据与冲突声明；人工确认/拒绝及原因，不给个人秘密评分。
- LearningBrief：学习目标、教师负责人、评价标准、学期、参与及成果许可、跨届交接。
- AdoptionDecision：接收机构、决定 continue/pilot/stop、理由、证据、预算授权、后续负责人。
- Evidence/Consent/Audit：基线、原型、测试、学习和采用分层记录；公开授权、脱敏检查和变更日志。

服务端访问是“城市范围 ∩ 项目/机构授权 ∩ 可见范围”。核心管理员不默认获得企业内容；需有明确机构授权。公开API只返回批准发布的投影。撤回访问不得只隐藏按钮。公开切换必须审核，默认私有，防止内部资料被GIS/搜索/导出旁路暴露。

## 12–16周试点（资源确认后开始）

与既有城市90天筹建并行衔接，联合试点不是另一项已经完成的承诺。一个城市及四类本地机构、一小组全球专家；一个大学社区挑战和一个企业挑战。

- 第1–2周：章程、授权、两个负责人/简报、基线、预算与接收机构就绪；不就绪延期。
- 第3–5周：利益相关方研究、准备度审核、人工匹配组队、课程简报。
- 第6–10周：工作坊、原型测试、证据及失败原因记录；必要时停止。
- 第11–16周：接收机构决定、教学评价、成本复盘、交接与经授权方法沉淀。

验收：两份完整简报、受影响群体反馈、明确实施决定、预算和责任落实、可复用城市手册。分别统计准备度通过率/原因、匹配接受率、里程碑证据、学习成果、采用决定与后续真实结果；参与人数不充当影响。长期效果需后续复核。
